# Конференции.РФ — учебный проект

Сайт для подачи и обработки заявок на конференц-залы. Создан по темам курса: Node.js + Express, HTML-формы, EJS, SQLite, ООП, сессии и Bootstrap.

**Это серверное приложение, а не статический сайт.** GitHub хранит исходный код; для открытия работающего сайта необходимо запустить Node.js на компьютере или сервере.

## Установка

Понадобится **Node.js 22+** и npm.

```bash
npm ci
npm start
```

Откройте **http://localhost:3000**. При первом запуске создастся `conf.db` с демонстрационными данными.

Дополнительные команды:

```bash
npm run dev      # перезапуск при изменении server.js
npm test         # проверки в папке tests
```

## Вход для демонстрации

| Роль | Логин | Пароль |
| --- | --- | --- |
| Пользователь | `student` | `Student123!` |
| Администратор | `Conf2027` | `Demo77` |

Это только для локальной демонстрации. Если планируется публичный запуск, до **первого** создания базы нужно задать `DEMO_ADMIN_PASSWORD` и `SESSION_SECRET`. Пароль уже созданного пользователя автоматически не изменяется.

## Что проверять на сайте

1. На `/rooms` выводятся помещения из таблицы `rooms`; кнопки фильтруют по типу.
2. На `/register` форма проверяет логин, пароль, ФИО, телефон и email. При неверных данных показывает ошибки; повторный логин не допускается.
3. На `/login` пароль проверяется через bcrypt; после успешного входа создаётся сессия, выход — через `/logout`.
4. На `/create` пользователь выбирает зал, будущую дату и способ оплаты. Новая заявка получает статус «Новая».
5. На `/dashboard` пользователь видит только свои заявки. `/request/:id` недоступен посторонним.
6. На `/admin` администратор меняет статусы. При назначении проверяется, не занят ли зал в этот день другой подтверждённой заявкой.
7. На странице заявки администратор отмечает оплату вручную; действие сохраняется в таблице `payments`.
8. После статуса «Завершено» автор заявки может один раз оставить отзыв; он сохраняется в `requests.review`.

**Примечание:** выбор способа и отметка оплаты — учебная логика. Банковских переводов, кассы или интернет-эквайринга здесь нет.

## Маршруты

| Метод | Адрес | Что делает |
| --- | --- | --- |
| GET | `/`, `/rooms`, `/rooms/type/:type` | Каталог и категории |
| GET / POST | `/register` | Регистрация |
| GET / POST | `/login` | Вход |
| POST | `/logout` | Выход |
| GET | `/dashboard` | Мои заявки |
| GET / POST | `/create` | Создание заявки |
| GET / POST | `/admin` | Управление заявками |
| POST | `/admin/payment` | Отметка оплаты (только админ) |
| GET | `/request/:id` | Подробности заявки |
| POST | `/review/:id` | Отзыв после завершения |

## Как работают основные файлы

- `server.js`: принимает GET/POST запросы, выполняет проверки и вызывает методы моделей. SQL-запросов здесь нет.
- `db.js`: создаёт таблицы, использует подготовленные SQL-запросы и классы ES6. `Requests.create` записывает заявку и запись об оплате в одной транзакции.
- `validation.js`: серверная проверка входных данных. Атрибуты `required` в HTML не заменяют эти проверки.
- `views`: EJS-шаблоны вставляют значения через `<%= ... %>` и общие части через `<%- include(...) %>`.
- `public`: статические стили и JS, которые отдаёт `express.static()`.

## По лекциям преподавателя

В проекте отражены темы «Введение в Node.js + Express», «Маршруты и формы», «Введение в EJS», «Include и структура проекта», «Введение в базу данных SQLite», «Связи и FOREIGN KEY», «Классы ES6 и ООП», «Использование классов в server.js», «Настройка сессии», «Регулярные выражения в валидации проекта», «Регистрация и авторизация с табами», «Страница просмотра заявки и форма отзыва», «ER-диаграмма, schema.sql, README», «Анимации, адаптив, финальная сборка».

Включены оба срока сессии (2 часа и 20 минут бездействия), `requireAuth` и `requireAdmin`, локальный Bootstrap, адаптивная сетка под 390×844, небольшие CSS-анимации. Дополнительно выполнено практическое задание из лекции по FOREIGN KEY: создана таблица `payments` и `JOIN` четырёх таблиц.

Код ориентирован на локальную учебную демонстрацию. Стандартное MemoryStore в `express-session` не подходит для промышленного многопользовательского сервиса.
