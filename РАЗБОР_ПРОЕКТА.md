# Как объяснить сайт преподавателю

Проект решает простую задачу: пользователь выбирает помещение и отправляет заявку. Заявка попадает в базу данных, а администратор меняет её статус.

## Регистрация

В `auth.ejs` находится форма с `method="POST"` и `action="/register"`. Express получает данные в `req.body`, `validateRegistration()` проверяет значения с помощью регулярных выражений, а `User.create()` записывает их в `users`. Пароль хранится как bcrypt-хеш, не обычный текст.

## Сессия

После проверки пароля при входе ID и роль пользователя записываются в `req.session.user`. При следующем запросе сервер понимает, кто вошёл. `requireAuth` не пропускает гостя к заявкам, `requireAdmin` проверяет роль администратора. Сессия имеет срок действия 2 часа; после 20 минут бездействия вход сбрасывается.

## База данных

Основные сущности: пользователи (`users`), комнаты (`rooms`), заявки (`requests`). В таблице заявок два внешних ключа — `user_id` и `room_id`. Четвёртая таблица `payments` добавлена по домашнему заданию. Четыре таблицы соединяются в `Requests.findAllDetailed()` с помощью `JOIN`.

## Создание заявки

В `create_request.ejs` есть `<select>`, `<input type="date">` и выбор оплаты. Маршрут `POST /create` проверяет, существует ли выбранная комната, дата не прошла ли, не занят ли зал. Метод `Requests.create()` выполняет SQL `INSERT`.

## Работа администратора

В `/admin` показаны заявки всех пользователей. После отправки формы `POST /admin` проверяется статус и выполняется SQL `UPDATE`. На странице подробностей администратор отдельно может изменить отметку об оплате через `POST /admin/payment`.

## Отзыв

Автор может оставить отзыв только после завершения своей заявки. `POST /review/:id` проверяет права и статус. `Requests.addReview()` обновляет поле `review`, если оно пустое. Повторно писать нельзя.

## Что можно показать на защите

1. Изменить название комнаты в `db.js` (для уже созданной базы — изменить запись через SQLite, потому что стартовые данные создаются один раз).
2. Показать фильтр на `/rooms` и маршрут `GET /rooms/type/:type`.
3. Зарегистрировать нового пользователя, показать сообщения при ошибочной регистрации.
4. Создать две заявки на один зал и дату, продемонстрировать проверку конфликта при подтверждении.
5. Зайти под администратором, завершить заявку, выйти и оставить отзыв под пользователем.
6. Открыть `docs/er_diagram.png` и показать связи таблиц.

**Совет:** перед защитой самостоятельно пройдите этот сценарий и попробуйте объяснить каждую строку `server.js`, связанную с формами. Не стоит говорить, что вы разрабатывали или тестировали части проекта, которых не понимаете.
